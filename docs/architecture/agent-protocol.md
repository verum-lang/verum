# Agent Protocol — сеансовая машинная поверхность компилятора

Status: ACCEPTED (T0853), дуэль закрыта 2026-08-22. Вердикт
holon-e2: принято с восемью ударами — все вписаны ниже (закон
владения потоком, required/advisory-поля, контент-адресация ответов,
журнал/реплей, бюджеты дорогих методов, cancel, двухфазный refactor,
закон поколений). Направление подтверждено владельцем: «новый
стандарт эры coding-агентов».

## 1. Тезис

Агент сегодня разговаривает с компилятором через CLI, созданный для
человека: холодный старт на каждый вопрос, прогресс-нарратив в
stdout, парсинг человеческих сообщений. LSP — машинный, но его
словарь — редакторский (позиции, подсветка), не инженерный
(поверхности, суды, доказательства, диффы).

Agent Protocol — это ТРЕТЬЯ поверхность, ранга LSP: один процесс
(`verum serve --agent`), один сеанс, JSON-RPC 2.0 поверх stdio,
словарь вопросов инженерного уровня. Не замена CLI и LSP — их
родной брат, деливший с ними одну реализацию (те же
`arch_query_module`, те же фазы, тот же инференс — ноль вторых
дериваций).

## 1a. Закон владения потоком (удар 1)

stdout принадлежит протоколу ЦЕЛИКОМ: один посторонний print рвёт
фреймы. Весь нарратив (прогресс, логи) — в stderr. Фрейминг —
LSP-стиль `Content-Length`, чтобы рваная запись ДЕТЕКТИЛАСЬ, а не
тихо съедала соседний ответ.

Мульти-агент на один сеанс — АНТИ-цель, не будущая фича: сеанс —
рабочая память ОДНОГО агента; деление создаёт семантические гонки на
оверлеях буферов, которые не лечит транспорт. Мульти-агент = N
процессов + VCS как точка слияния. Socket-транспорт — ископаемой
датой в будущее.

## 2. Словарь v1 (append-only с ископаемыми датами)

| Метод | Вопрос | Ядро ответа |
|---|---|---|
| `session.open` | параметры проекта (root, target) | session_id, версии схем |
| `parse.check` | «парсится ли этот файл/буфер?» | диагностики (стабильные коды) |
| `check.types` | «типизируется ли?» | диагностики |
| `arch.query` | «что может этот код?» | ArchQueryReport (существующая схема) |
| `arch.diff` | «как патч меняет поверхность?» | дельта атомов (widen/narrow), per-fn |
| `test.run` | «проходят ли тесты X?» | вердикты + JSON-отчёт |
| `tiers.diff` | «тиры согласны об этой программе?» | DiffTiersReport (существующая схема) |
| `verify.obligations` | «какие обязательства у fn и их статус?» | список: discharged/failed(+CEX) |
| `verify.discharge` | «попробуй разрядить с бюджетом s» | вердикты + MISSED при превышении |
| `session.journal` | «покажи журнал диалога» | контент-адресные записи |
| `session.replay` | «воспроизведи журнал» | детерминированный повтор |
| `$/cancel` (notif) | «отмени запрос id» | прерывание без убийства сеанса |
| `cex.materialize` | «сделай из контрпримера тест» | путь `.vr`-файла (T0856) |
| `refactor.apply` | «примени закон X с сертификатом» | диф + сертификат (T0855) |

Правила словаря — дисциплина AP-кодов: методы и поля append-only;
устаревание — пометкой с датой и преемником, никогда удалением.

**Конверт и поля (удары 2, 3, 8, provenance):**

* Конверт: `{protocol_version, method_version, data}` — конверт
  меняется ~никогда, версии методов независимы.
* Каждое поле маркировано `required-for-correctness` или `advisory`
  (Л-2-закон: неизвестное REQUIRED-поле клиент ОТВЕРГАЕТ, а не
  полу-читает; advisory — пропускает; культура может опережать
  читателя без лжи).
* **Контент-адресация**: каждый ответ ЦИТИРУЕТ hash буфера/дерева,
  о котором отвечал — агент сверяет, что ответ о том, что он послал;
  desync-класс умирает, аудит и реплей бесплатны.
* **Закон поколений**: ответ несёт generation/hash состояния дерева;
  оверлей буфера побеждает диск до закрытия; изменение диска ПОД
  оверлеем (git checkout самого агента, параллельная сборка) —
  именованная staleness-диагностика, никогда тихий merge.
* **Provenance в v1**: вердиктные ответы несут
  `{computed_from: {hashes, config, tool_version}, evidence:
  Computed|Cited}` — двухъярусная улика ATS-V-2 в каждом ответе.
  Криптоподпись — конвертом позже (ретрофит provenance ломает
  append-only, ретрофит подписи — нет).
* **Бюджеты**: всякий дорогой метод (verify.discharge, test.run)
  берёт явный бюджет `s` и возвращает MISSED-честность при
  превышении — anytime-дисциплина; время — гражданин протокола.
* Коды диагностик — ЧАСТЬ поверхности протокола (append-only с
  датами, как AP-коды).

## 3. Сеансовость

- Буферы: ПОЛНЫЕ в v1 (каждое сообщение переустанавливает истину —
  идемпотентно, реплеябельно, детерминизм-дружественно;
  didChange-диффы — известный класс шрамов рассинхрона, ископаемой
  датой позже). Переиспользование parsed/checked артефактов между
  вопросами — машинерия IncrementalDocument из verum_lsp.
- Один сеанс = одна session (наша `Session` со всеми реестрами:
  arch-shapes, fn-summaries, protocol max-shapes) — вопросы видят
  согласованное состояние, а не N независимых компиляций.
- Конкурентность v1: последовательная обработка (очередь);
  параллелизм — после стабилизации словаря.

## 4. Агентский цикл (несущий сценарий)

```
session.open
→ arch.query (до)             # что можно
→ [агент пишет патч в буфер]
→ parse.check / check.types    # быстрая валидация
→ arch.diff (буфер vs диск)    # самоограничение до сабмита
→ tiers.diff                   # тождество тиров на репро
→ verify.obligations           # долги доказательств
→ submit (вне протокола — VCS)
```

Каждый шаг — один RPC без перезапуска процесса; стоимость вопроса —
миллисекунды после первого.

## 5. Безопасность и границы

- Протокол НЕ исполняет произвольные команды: словарь закрыт,
  каждый метод — именованная способность (сам протокол получает
  @arch_module-пин с exposes по своим методам — dogfooding ATS-V-2).
- **Теорема границы (удар 7)**: протокол ЧИТАЕТ дерево, ПИШЕТ
  только объявленные артефакт-каталоги, а source-диффы ВОЗВРАЩАЕТ
  ДАННЫМИ. `refactor.apply` двухфазен: протокол отдаёт диф +
  сертификат, применяет АГЕНТ своей VCS-подконтрольной рукой.
  Закон домен-потока ATS-V-2 применим к самому протоколу: путь вне
  объявленных каталогов в ответе — машинно-ловимое нарушение
  собственного пина.
- Никакой сети. Протокол локален по построению.

## 6. Отношение к существующему

- CLI-команды становятся тонкими клиентами тех же внутренних
  функций (уже так: arch query / diff-tiers зовут общие модули).
- T0849 (ask/diff) РЕАЛИЗУЕТСЯ этим протоколом (метод arch.diff +
  негатив-фикстур на трёх транспортах: CLI, LSP-мост, protocol).
- vtest/аудит остаются batch-инструментами; протокол — интерактив.
