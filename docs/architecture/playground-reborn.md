# Playground Reborn — одно стекло для новичка и исследователя

Status: ACCEPTED (T0858), дуэль закрыта 2026-08-22. Вердикт
holon-e2: тезис принят, пять вопросов закрыты, четыре удара вписаны
(линза CEX, Evidence-колонка, бейдж цены, линза DIFF). Мандат
владельца: «playground кривой-косой, непонятно как пользоваться;
переосмыслить фундаментально — полезный инструмент для новичков И
исследователей, кому нужна предельная продуктивность и внутренние
детали».

## 1. Диагноз (по коду, не по ощущению)

1. **Имя без входа.** Доки обещают «browser playground» (не
   существует); существующий инструмент зовётся `verum playbook` —
   новичок не находит ни того, ни другого. Вход не одно-командный.
2. **TUI изолирован от истины компилятора.** Сайдбар — Variables /
   Outline / DevTools. НЕТ: типов и инференса, arch-поверхности,
   VBC-байткода, тир-сравнения, verify-обязательств. Исследователю
   «внутренние детали» недоступны в принципе — а это ровно те
   поверхности, которые сегодня получили машинные словари
   (arch.query, diff-tiers, verify.*).
3. **Вторая интеграция исполнения.** `verum_interactive::execution` —
   собственный мост в интерпретатор, параллельный компиляторному
   API. Redundancy-класс: третий клиент одной семантики должен жить
   на ТОМ ЖЕ словаре, что CLI и агенты.
4. **Ноутбук без закона воспроизводимости.** Ячейки не
   контент-адресованы; реплей .vrbook не гарантирован бит-в-бит —
   мимо детерминизм-конституции, на которой стоит весь остальной
   инструментарий (K-3 стенда, session.journal).
5. **Невидимая карта действий.** Режимы и клавиши существуют, но
   экран их не преподаёт — «непонятно как пользоваться» это не
   отсутствие фич, а отсутствие ВИДИМОЙ карты следующего действия.

## 2. Тезис переосмысления

**Playground — это человеческий клиент той же машинной поверхности,
которой пользуются агенты.** Не третья реализация истины, а третий
транспорт одного словаря (CLI → люди-скрипты; Agent Protocol →
машины; Playground → люди-интерактив). Каждая панель «внутренних
деталей» — это отражение существующего append-only ответа протокола,
с нулём вторых дериваций.

## 3. Форма

### Вход
`verum play [file.vr|file.vrbook]` — единственная команда входа
(playbook остаётся алиасом). Пустой запуск открывает ГАЛЕРЕЮ:
туры для новичка (builtin_tutorials — уже есть, оживить) + недавние
книги + пустой лист.

### Ячейки = вопросы; сеанс = растущий модуль (закон состояния)

**Состояние живёт в ВОПРОСЕ, не в сеансе** (вердикт дуэли, наш канон
«в один носитель сводится вопрос» дословно). Ячейка k — это
{контент-адресная цепь модуля-до-k, текст ячейки}: исполнение —
test.run над ВЫРОСШИМ МОДУЛЕМ с нуля, детерминированно;
runtime-состояние между ячейками НЕ живёт. `session.eval` со
состоянием ОТВЕРГНУТ — stateful-метод был бы «второй интеграцией»,
переродившейся внутри протокола (second-truth класс).

Мировой урок в поддержку: скрытое состояние Jupyter — прожитая язва
невоспроизводимости ноутбуков; Pluto.jl выбрал recompute-from-source
и выиграл воспроизводимость. Мы выбираем то же — по конституционным
причинам, не по вкусу. Переопределение имени в поздней ячейке — рост
модуля по закону шэдоуинга ЯЗЫКА: ноутбук не получает магии, которой
нет у языка; конфликт — честная диагностика.

Ответ ячейки цитирует hash цепи ⟹ **.vrbook v2 = сама цепь**,
реплеябелен бит-в-бит бесплатно (реплей = прогон цепи; расхождение
называет ячейку — K-3/K-4 дисциплина в документе исследования). Кэш
по неизменному префиксу цепи даёт REPL-скорость
(Incremental-машинерия существует). Протоколу — максимум
конвениенс-метод «вопрос-с-цепью», чистый по построению.

### Линзы (Tab-панели правого стекла)
Одна ячейка — много истин; линза выбирает, какую показать:

| Линза | Что показывает | Источник (ноль вторых дериваций) |
|---|---|---|
| Result | вывод + человеческие диагнозы | test.run / parse.check |
| Types | выведенные типы биндингов ячейки | infer-поверхность (readonly) |
| Arch | inferred/pinned/суд ТЕКУЩЕГО буфера вживую | arch.query |
| VBC | байткод ячейки (дизассемблер) | существующий disasm |
| Tiers | вердикт diff-tiers по требованию | tiers.diff |
| Verify | обязательства и статус (и2: с бюджетом) | verify.* |
| CEX | контрпример красного verify + клавиша «сделай тестом» | cex.materialize |
| Diff | arch.diff буфер-против-диска: как патч меняет поверхность | arch.diff |
| Journal | стеклянный ум сеанса: кадры + хэши | session.journal |

Поверх линз — два сквозных элемента (удары дуэли):
* **Evidence-колонка** на КАЖДОЙ линзе (Computed/Cited у каждого
  ответа) — аудит всегда на виду, не спрятан в Journal.
* **Бейдж цены** на каждой ячейке: секунды compile/run/verify +
  MISSED-честность бюджета — «предельная продуктивность» начинается
  с видимости, куда уходит время.

Новичок живёт в Result и не видит остального, пока не попросит;
исследователь листает линзы Tab'ом. v1 — код + ОДНА активная линза
(дисциплина фокуса: «одна ячейка — много истин; линза выбирает»);
мульти-сплит — v2 по спросу. CEX-линза замыкает исследовательскую
петлю: красное доказательство → контрпример → одна клавиша — и он
регрессионный тест.

### Видимая карта действий
Строка статуса ВСЕГДА показывает 3-5 контекстных клавиш («что я могу
нажать сейчас»); `?` — полный оверлей-справка; первая сессия
открывает интерактивный тур (одна клавиша до «hello world бежит»).
Излечение «непонятно как пользоваться» — это дисциплина видимости,
не редизайн клавиш.

### Смерть второй интеграции
`verum_interactive::execution` мигрирует на компиляторный API/словарь
протокола срезами; конечное состояние — TUI не знает интерпретатор
лично, только словарь вопросов. (Дорога, не большой взрыв: линзы
Arch/Tiers/Journal идут через словарь с первого дня; Result-миграция
последней.)

## 4. Дорога срезов

1. **Вход + видимость**: `verum play`, галерея, статус-подсказки,
   `?`-оверлей. (Дёшево, снимает главную жалобу.)
2. **Линза Arch** — первое стекло исследователя (arch_query_source
   in-process, уже есть); Types-линза readonly.
3. **Линза VBC + Tiers** (disasm ячейки; diff-tiers по кнопке).
4. **.vrbook v2** — цепь контент-адресов (книга = цепь) + реплей
   `verum play --replay book.vrbook` с вердиктом бит-в-бит; живая
   книга хранит hashes + Result (реплей довычисляет линзы), полные
   ответы — только явным экспортом `--freeze` (замороженная книга =
   ОТЧЁТ со снапшот-хэшами; живая = истина; полные ответы в живой —
   дрейф-класс второй истины).
5. **Сеанс поверх словаря протокола** + Journal-линза; миграция
   Result.
6. Туры: ЖИВУТ в docs/by-example, бинарь встраивает их на сборке из
   того же источника (include-на-сборке — ноль дрейфа, оффлайн
   есть); builtin-копии рядом с доками ЗАПРЕЩЕНЫ (одна истина
   примеров). Три новичковых + исследовательский «прочти свою
   программу семью линзами».

## 5. Вопросы дуэли (разрешены)

(1) v1 = код + одна активная линза; (2) hashes+Result в живой книге,
полные ответы — только `--freeze`-отчётом; (3) накопительный сеанс =
растущий модуль с контент-адресной цепью, session.eval-с-состоянием
отвергнут (состояние живёт в вопросе); (4) одна истина примеров —
туры из docs/by-example, встроенные сборкой; (5) четыре удара
вписаны: линза CEX, Evidence-колонка, бейдж цены, линза Diff.
