# What an architecture check establishes

A reviewer of the registry needs to be able to follow a published cog from the HTTP route through the PostgreSQL transaction to the bytes a fresh client installs. A list of imported modules answers a different question. An architecture report should identify which of those questions it answered, the input it inspected and which edges it could follow.

## Findings from the VSA proposal

| Claim under review | Evidence in the implementation | Engineering consequence |
| --- | --- | --- |
| Architecture inference uses call-name heuristics. | `arch_capability_inference::lookup_capability` classifies paths. The compiler also solves recursive function summaries, resolves explicit mounts through its compilation session and reads protocol bounds in `pipeline/ats_v_phase.rs`. The single-file query has no compilation-session import registry. The corpus audit separately classifies mounts. | Preserve the solver. Move primitive semantics to declaration identities and project resolved calls into its inputs. Classify a mount as a dependency, never as evidence that its code executed. |
| Row equality and resource refinement are defective. | The original ordered map used Rust debug strings as semantic keys. Rows now use typed keys. File scopes still include string patterns, and the path classifier can produce the literal `<inferred>`. Exact structural equality cannot decide permission containment. | Represent unknown scope separately from an explicit all-resource authority. Keep exact identity separate from authorization to access a subset. A dynamic path can require an obligation without proving a dead right. |
| A quiet diagnostic means the check succeeded. | Several fields in `arch_anti_pattern::DiagnosticContext` default to empty. The compiler supplies peer/tier and transitive lifecycle information, while inputs such as observer verdicts can be empty. The audit's inactive-check counts refer to an older phase file. | Track availability per check and input scope. Distinguish an analyzed empty set from a missing producer. Accept a negative finding only when that producer covered the claimed domain. |
| Metadata comparisons prove safe refactorings. | `analyze_refactoring` synthesizes the inverse-name witness it checks. `yoneda_equivalent` really compares two shapes, but only through the requested finite observer roster. The CLI also exercises known synthetic shapes. The intrinsic proof boundary already returns `StructuralOnly`. | Keep shape comparisons as diagnostics. A proof of replacement needs a specified observation, state relation and obligations on the actual operations. A smoke-test result belongs to the checker, not to the user's project. |
| Lifecycle tags and measured topology can substitute for assurance. | The current ring checker found 2,559 modules, 6,422 inter-module edges, three declared exceptions and zero violations. This measures the ring checker's graph. A lifecycle annotation conveys author intent. | Keep ring, call and trust graphs separately identified. Require parity of edges, exceptions and counterexamples before retiring the existing ring gate. |
| Moving files out of the kernel reduces trust. | Architecture analysis and proof checking share a Rust crate. The proof-admission interface already distinguishes a structural result from an admitted proof. | Trace the entry points that can admit a theorem and their dependencies. Extract analysis behind data interfaces as those dependencies are severed. Source line count alone cannot measure a trusted computing base. |
| New surface grammar should come first. | Existing protocols, context layers, refinements, contracts, ownership checking and the proof kernel already govern parts of the proposed syntax. | First lower each proposed construct to existing checks and give it a rejection case on ordinary code. Add syntax where it removes repeated obligations while preserving those checks. |

The row implementation exposed two additional failures. An SCC could retain `Computed` after a recursive callee introduced a citation for the same atom. A missing callback row could silently become empty. Fixed-point equality now includes provenance. Simultaneous, binder-scoped substitution preserves an unresolved callback until an actual argument supplies its row. A retained citation names one deterministic witness. It is insufficient for a complete dependency inventory.

## Semantics to share across tools

* A computational property describes an operation. A capability authorizes an operation on a resource. A context requirement identifies a service that must be supplied. Giving a function a database implementation discharges its need for a provider. The implementation's network and persistence requirements still flow to the assembly. Derive these projections from the same resolved operation with a source location.
* Record an observation against the exact module, declaration, specialization, target and inputs analyzed. A typed call edge, protocol maximum, external declaration and runtime observation have distinct evidence. Preserve unknown edges and the assumptions behind cited bounds. Cache keys must include the relevant declaration and implementation dependencies.
* Interpret permissions in a declared resource model. A literal path prefix alone cannot establish that a file open stays inside a directory in the presence of parent traversal, symlinks and concurrent renames. A directory handle with constrained traversal can provide an enforceable boundary. Protocol and direction on a network capability say nothing by themselves about a peer's authenticated identity.
* Separate a result about metadata, a checked source theorem, independent replay and correspondence with an executable. Preserve theorem identity, assumptions, source binding, target and checker identity. A numeric minimum over public declarations loses this information. Proof obligations on a port must cover each implementation reachable through that port.
* State replacement depends on traces. For each permitted transition of the replacement, show the specified matching observation and a related successor state. Make refusal, failure, divergence and scheduling assumptions explicit when observable. A round trip can establish a retraction. An adjunction additionally needs its specified order or hom-set law. Neither follows from inverse function names.
* The linear-time Tarjan bound applies to graph condensation. Propagating parameterized summaries costs additional time determined by lattice height, row size and call-site substitutions. Refinement implication may time out. A timeout leaves an outstanding obligation. Measure latency and peak memory on the registry before choosing indexing or widening policies.

These distinctions have precedents in the separation of proof checking from statement validation, control-flow-based loan analysis and target-specific semantic preservation. [Lean proof validation](https://lean-lang.org/doc/reference/latest/ValidatingProofs/) · [Rust borrow checking](https://rustc-dev-guide.rust-lang.org/borrow_check.html) · [CompCert guarantees](https://compcert.org/man/manual001.html)

## Migration gates

| Layer | Ordinary entry point and counterexample | Acceptance evidence |
| --- | --- | --- |
| Resolved project graph | Run the compiler and Studio on the registry. Rename a filesystem wrapper, shadow its old name with a pure function, change an imported implementation, then call through a protocol. | CLI, Studio, LSP and agent consumers reference the same resolved declaration and artifact identity. Unknown dispatch remains visible. A shadowed name grants no authority. |
| Topology and scopes | Recheck the stdlib and registry with an illegal upward edge, a permitted cohesive cycle, a dynamic file path and a narrow path claim. | Explain the edge or unsatisfied scope with source locations. Retire the external ring checker only after comparing its accepted corpus and rejection cases. |
| Ownership and suspension | Return a map-entry loan through a generic sum, move its owner, or keep an explicitly suspension-sensitive handle live across an await. Include a sibling that releases the loan first. | Check the lifetime on real control flow and every VBC path that consumes the reference. Stale or forged runtime handles fail before address access. |
| Execution envelopes | Compare allocations and blocking calls across interpreter, native, and foreign implementations. | Give each guarantee a target, operational definition and evidence producer. Constant-time or worst-case latency claims require a specified observation and execution model. |
| Proof and trust | Swap a persistence implementation for one that acknowledges before commit. Try reusing a proof after changing the acknowledged operation. | Recheck the actual source transition and its refinement relation. Surface foreign assumptions and changed dependencies. Bind replay to the current theorem and artifact. Use real PostgreSQL publish, restart and fresh install as a separate operational check. |
| User interfaces | Request a project result with a missing provider, a partially analyzed callback or stale metadata. | Report incomplete evidence with navigation to its cause. A fixture pass, a partial fingerprint and a proof of the user's project have distinguishable machine-readable outcomes. |

The VSA sketches for kernels, rendering, storage, networks, consensus and agent hosts exercise different guarantees. Device ownership and DMA need a stated hardware boundary. Frame budgets need a cost model. WAL ordering needs a crash model. Wire ports need a codec law and peer model. Consensus needs a fault and scheduling model. An agent host needs capability enforcement around the actual tool invocation. These are adequate first consumers for separate checks, rather than grounds for one universal assurance grade.
