# Verum Studio research and development architecture

A researcher should be able to start with a question, find the relevant definitions, run a Verum experiment, state a stronger claim, inspect its assumptions and give another person enough information to reproduce the result. A monorepo maintainer should be able to follow the same path from a proposed change to the affected cogs, callers, contracts and release checks. Both workflows need stable subjects, scoped authority and inspectable evidence.

## What the host already provides

Studio exposes its project model, diagnostics, definitions, edit proposals, operations and retained receipts through the same Rust services used by its editor. The project language service captures source identities and distinguishes indexed files from analyzed documents. Verum's compiler agent protocol also exposes architecture queries and execution-tier comparisons. Its session methods can be discovered at runtime. A checker or capability planned in a design becomes available to a client only when the host advertises and implements it. See the [compiler agent protocol](agent-protocol.md).

The current Studio transport uses Codex. An author and an independent reviewer can work in separate conversations. The host owns each role and the review classification of each registered tool. Each live approval has a fresh host identifier and an originating conversation. A reviewer reads the task, saved project artifacts and selected receipts. Source writes and run, check or proof jobs require author authority and operator approval. The operator chooses what is sent to each provider. The browser bearer token grants workspace access to its holder. Conversation scoping prevents accidental cross-talk within that trust domain. Hosting mutually untrusted users requires distinct principals and access controls.

## The common model

| Object | Identity and responsibility |
| --- | --- |
| Workspace revision | Selects cog manifests, dependency resolution, source overlays, library metadata, target and toolchain. Track inputs actually read so unrelated changes can reuse pure results. |
| Subject | A qualified declaration within its cog and revision, a byte-addressed dataset, an instrument run or a formal proposition with its assumptions. A file path or display name alone is insufficient. |
| Obligation | Names its subject, quantifiers or measurement domain, required evidence kind, verification procedure and budget. The project owner protects these acceptance rules from edits by the actor being evaluated. |
| Run | Names one invocation, tool and configuration, exact inputs, termination and produced artifacts. Interrupted and exhausted runs keep their identity. |
| Claim and evidence edge | Records who asserted a claim, the exact source span or artifact supporting it, and the relation checked. A review finding, observed output, kernel judgment, independent replay and native correspondence each answer a different question. |
| Workflow revision | Names the owner, permitted operations, inputs, guards and expected outputs of a Verum procedure. Changes undergo review and replay before activation. |

Architecture as Type should project these relationships from the compiler. Start from cog boundaries, resolved mounts, declarations, field dependencies, declared contexts and contracts. Overlay obligations and run results only where their subjects match. Give every edge a navigable origin and every query a coverage indicator. A lexical match may suggest a module to inspect. Only a resolved compiler binding establishes a source dependency. Several cogs can export a declaration with the same spelling.

## Provider orchestration

Give each configured provider instance an identity independent of model name. Its adapter negotiates account availability, model discovery, cancellation, reviewed tools and continuation. Bind the instance, workspace revision, role and policy to each conversation. Each turn belongs to one conversation. A participant hands off a task, selected artifacts and open objections. The recipient can inspect the original evidence and use a different model. The operator sets disclosure, time, token and concurrency budgets for each task.

Keep tool admission in the Verum host. While independent reads run concurrently, file updates compare the saved content hash. A future multi-file change requires one transaction over the checked base revisions, with explicit conflict review. Persist task and operation events with causal IDs, bounded output and idempotent delivery. On restart, reconcile pending work with the actual worker and expire approvals with their originating session. Today's provider journal is bounded and in memory. Durable cross-provider orchestration is a separate implementation milestone.

T3 Code separates driver capabilities from configured instances and represents sessions, turns and runtime requests explicitly. Its recovery logic reconciles work after restart, and its checkpoint policy checks whether other threads share a working directory. Each Verum adapter should pass admission tests for missing authentication, interleaved requests, capability refusal, interruption, duplicate delivery and process loss before it appears as usable. ## A Verum-native project and research workflow

A project declares named tasks with typed inputs, outputs, context requirements and dependencies. A task may reference another cog or a pinned dataset. The scheduler resolves the graph, diagnoses cycles, selects independent steps within resource limits and records each attempt. Cancellation prevents new dependents from starting and preserves completed receipts. A task that publishes a cog has an explicit external commit point and idempotency key. The registry acknowledges durability before the host records publication. Agent-authored tasks and Studio extensions run through the same admission and permission checks as handwritten ones.

An extension contributes typed commands, projections or experiment procedures. Its manifest declares required host capabilities and supported schema versions. Studio exposes narrow operations for reading a graph slice, rendering a view, proposing a change or requesting a job. Credentials and arbitrary host filesystem access stay with the owning adapters. Execution of untrusted extensions requires enforced memory, time and context limits with cancellation. This requirement applies to interpreted Verum as well as native code.

For a large workspace, identify a cog by its manifest, resolved dependency identity and selected target. The same source path can be compiled against different dependencies. Use the language service's observed dependency reads for invalidation. A graph request specifies revision, scope, direction and frontier budget, and returns continuation plus coverage. An unresolved import stays visible with its diagnostic. The editor, web UI, CLI and provider tools consume the same edge identifiers and source ranges. On a changed revision, navigate to a new declaration only after resolving its identity again.

A worked research path begins with a physicist's conservation hypothesis. A Verum script imports the calibration and measurement data, reports residuals with units and records the input hashes, precision and tolerance. A mathematician states the analytic invariant over the idealized model and replays its proof. An engineer proposes an optimized implementation and checks refinement against that model as a separate obligation. The same project can keep an empirical discrepancy, a proven analytic invariant and an unresolved refinement visible at once. Changes to the calibration reopen the measurement analysis. Changes to the formal assumptions reopen the theorem's dependents.

## Retrieval, learning and verification

1. **Independent review.** Give a fresh critic the task, changes and specific evidence. Let it challenge a missing premise or request a new check. The verifier alone issues a judgment for its declared proof profile. Independent review improved benchmark performance in the published experiments. Transferring that result to large Verum projects requires a separate evaluation. [Rethinking Verification in Agent Harnesses](https://arxiv.org/pdf/2610.34577).
2. **Scoped memory.** Assign each proposed workflow correction to an owner such as a project router, specialist procedure or local skill. Record the failure that motivated it and change one scope at a time. Evaluate on held-out tasks for that scope and unrelated tasks before accepting the change. Keep prompts and learned heuristics outside checker rules and authorization policy. [EMMA](https://arxiv.org/pdf/2610.35966).
3. **Guarded reuse.** A deterministic step can reuse an exact previous result when its inputs, observed dependency closure, tool semantics and budget-sensitive outcome support reuse. A changed guard returns control to the scheduler. Pure artifact lookup may be shared. A source change, publication or resource-consuming operation needs its own authority. Count fallback calls and failed episodes when measuring savings. [HarnessMM](https://arxiv.org/pdf/2610.32813).
4. **Structured navigation.** Let a person or model narrow the search from workspace to cog, module, declaration, obligation and source location. Rank alternatives under a shared budget. Keep exact lookup and a broader search available when ranking prunes a relevant branch. Academic corpora with headings and passages are a different workload from compiler-owned symbols and cross-cog reexports. [DecisionRAG](https://arxiv.org/pdf/2610.35868).
5. **Context compilation.** Materialize passages and claim–evidence pairs with source revisions, permissions and rebuild triggers. Keep machine-extracted structure separate from model-written summaries. Deliver a compact packet when it answers the query and expand into original sources on insufficiency. The authors report token savings and also a setting where an outline degraded results. Measure both retrieval and ingestion cost locally. [Context as Infrastructure](https://arxiv.org/pdf/2610.41172).

For mathematics, the packet carries the statement, environment, assumptions, proof object and replay identity. For a physical experiment, record raw data hashes, units, calibration, acquisition order, model assumptions and numerical tolerances. A theorem about the model and a measurement of the apparatus require different evidence. The registry gives a software counterpart. A successful component storage run does not exercise the HTTP listener, authentication, PostgreSQL transaction and restart together. Admission for durable HTTP publishing must exercise that path.

For a proof-bearing release gate, freeze the obligation before the actor submits a candidate. Bind the submitted proof to the statement, environment, source and toolchain identities. Run the supported native checkers and, for profiles with an independent export, replay in a separately identified Lean environment. Record the assumptions and the scope of the translation. Reject missing premises, unapproved axioms and unsupported constructs. A timeout remains inconclusive. A change to the formal statement requires a distinct obligation and explicit review. A native-correspondence claim additionally needs a checked connection from the implementation to that exact model and input. The agent that generated a proof cannot confer any of these statuses.

## Implementation and evaluation

Use Verum programs and cogs for experiments, transformations, workflow definitions and extension logic. Run the same source interactively via the interpreter and apply VBC or AOT where validated. Reuse the existing compiler, scripting library, project manifests and permission contexts. Keep provider transports, OS boundaries and device drivers explicit. Today's bootstrap host is Rust, the graphical client uses browser technology, and Lean can independently replay supported proofs. Self-hosting proceeds one service at a time, with the new implementation replaying the existing conformance corpus before replacement.

The next increment should implement a versioned evidence packet over existing compiler and operation schemas. Then add cog-aware graph queries and invalidation, followed by a second genuine subscription adapter and durable concurrent handoff. Compare exact lookup, lexical search, graph traversal and model-ranked traversal on the same held-out monorepo tasks. Record wrong-owner selections, dependency coverage, retrieval misses, stale reuse, unsupported obligations, bytes and tokens transferred, cold/warm latency and operator approvals. Separately measure experiment reproduction and proof replay. An optimization is eligible only while the required evidence and refusal tests remain valid.

The SYNARC team supplied a concrete acceptance case from the frozen native nomination at commit `45186ad70`. For the 1,401-observation window with 48 occupied cells, a theorem covers every positive fraction with the recorded numerator and denominator widths of 305 and 292 bits. Adding six to the frozen numerator gives another reduced fraction with the same widths. In exact arithmetic both products exceed one and both squares remain below (467/16)⁴⁸. A bound quantified over those widths remains applicable. Correspondence to the specific native invocation fails at the operand-reconstruction edge. Repeat with a changed source ordinal or definition identity. Preserve the original theorem and report the failed edge. In Studio the smaller regression executes two distinct scripts returning the same number and rejects a receipt query pinned to the other script's digest. This covers source identity only. Native operand reconstruction requires its own adapter and replay.
