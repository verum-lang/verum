# Regenerate by running `verum test --interp` over the whole suite and
# listing every file whose tests ALL fail with "compilation failed".
# Never by reasoning about a file: a dead one is indistinguishable from a
# live one by text.
#
# 2026-09-12, LATER: the three `async/poll/*` files came OFF this list.
# They were dead on one cause — task #22, constrained-implement-block
# dispatch, which binds `implement<T, E> Poll<Result<T, E>>` against a
# concrete `Poll<Result<Int, Text>>` in the WRONG PARAMETER ORDER. It is
# a COMPILE error, so no `@ignore` can contain it: one such call took all
# three files down. Rewriting nine call sites to pin the same properties
# through the Poll/Result algebra — the work-around this suite's own
# author had already used for one test — revived 87 tests, all green.
# That is the shape of the repair for the rest of this list: find the ONE
# construct, pin around it, name the task.
#
# Measured 2026-09-12 on the full suite — 19042 tests, 16542 passed,
# 2129 failed, 371 ignored, 2091s at 4 threads. 84 files account for
# 1774 of those failures: 9.3% of the suite never runs at all.
#
# 2026-09-12, LATER STILL: the four `sys/no_runtime/*` files came off this
# list without being repaired. They test `core/sys/no_runtime.vr`, which
# `core/sys/mod.vr` gates with `@cfg(runtime = "none" | "embedded")` and the
# default bake therefore EXCLUDES — the build prints "excluded 2
# runtime-gated file(s)". Their tests could never compile against the default
# archive, and the four `sys/embedded/*` files (never on this list) were in
# the same position. The test runner now consults the same
# `runtime_gated_modules` authority the bake does and skips them by name,
# so the default run no longer reports 39 failures for a module it does not
# contain.
